# 实测数据（MEASUREMENTS）

本文件里的数字都来自**单机、单账号、2026 年 9–10 月**的实测。换账号、换地区、换时段都可能不同——
所以每条都给出**复现方法**，而不是让你照抄结论。

> 原则：**"我量过"和"我觉得"是两回事**。下面凡是没量过的，一律标成「未验证」。

---

## 1. 分区可用率（普通账号，无大会员）

**判定"可用"** = 非会员可播（无 `redirect_url`）+ 有字幕轨 + 时长 3–60 分钟。
每区取排行榜前 12 条。

| 分区 | 可用 | 主要流失原因 |
|---|---|---|
| 美食 | 9/12 | — |
| 动画 | 8/12 | 部分无字幕 |
| 汽车 | 8/12 | — |
| 娱乐 | 7/12 | — |
| 游戏 / 生活 / 影视 / 科技 | 各 6/12 | 无字幕居多 |
| 全站 / 知识 | 各 5/12 | 无字幕 |
| 音乐 / 动物 | 各 2/12 | 时长太短 |
| **纪录片** | **0/12** | **8 条是会员专享**（302 到番剧页） |
| **电视剧** | **0/12** | **12 条全部会员** |
| **电影 / 鬼畜** | **0/12** | 会员 / 时长不合 |
| 舞蹈 / 时尚 / 运动 | 各 1/12 | 无字幕 + 太短 |

**结论**：如果目标是"学点东西"，**内容供给的瓶颈不是分区数量，而是"有字幕 + 非会员 + 时长合适"这三重过滤**。
按这张表砍掉纪录片/电视剧/电影/鬼畜，选片命中率立刻上一个台阶。

**复现**：对每个分区请求排行榜（`/x/web-interface/ranking/v2?rid=<rid>&type=all`），
逐条取 view + player 接口，统计 `redirect_url` 是否存在、字幕轨条数、时长区间。
（本工具只内置了判定逻辑，没有内置榜单爬取——那属于"选题"层，各人策略不同。）

## 2. 字幕覆盖率

- 抽样中**大多数视频的 AI 字幕轨覆盖 100%**（与视频时长一致）
- 但也遇到"看起来完整、其实只到 8 分钟"的情况——**必须按比例算，不能凭感觉**
- 有一条 8 分 8 秒的视频，转写最后一行是 `[00:08:06]`：**这是 99%，不是截断**

**代码里的处理**：`transcript` 会在文件头写 `字幕覆盖: xx%`，低于 80% 追加 ⚠️。

## 3. 抓帧体量与成本

| 指标 | 实测 |
|---|---|
| 单张全分辨率帧（1600×900, JPEG q0.9） | ≈ 180–250 KB |
| 每条视频存图数（`maxFrames=40`） | 40 张 ≈ **8 MB** |
| 采样的运行开销 | 每次只取 **32×18 灰度缩略图**做差分，很轻 |
| 读图成本 | ≈ **1300 token/张**（1280×720）；40 张 ≈ 5.2 万 token ≈ ¥0.052 |

**注意**：调大 `maxFrames` 只影响"密度"，不影响"覆盖"——覆盖由 `minGapMs` 决定
（详见 [`FAILURE-MODES.md`](FAILURE-MODES.md) 第 7 条）。

## 4. 上下文开销（1M 窗口模型，单次会话实测）

从会话日志里量出来的（脚本思路见下）：

| 指标 | 数值 |
|---|---|
| **固定开销基线**（系统提示词 + 工具定义 + 人格） | **9,011 token（窗口的 0.90%）** |
| 18 轮对话后 | **359,505 token（35.95%）** |
| 平均每轮增长 | ≈ **19.5K token** |
| **缓存命中率** | **99.2%** |

**两条推论**：

1. "固定开销吃掉一大块"要看窗口大小：20 万窗口下它是 19%，100 万窗口下只有 0.9%
2. 长上下文的第一代价**不是钱**（缓存命中让输入极便宜），而是**注意力稀释**——
   所以优化目标应该是"该看的信息有没有在上下文里"，而不是"token 省了多少"

**复现方法**：把会话日志按 zstd 魔数切帧解压 → 逐行 JSON → 取每条 `assistant/message` 的
`data.usage`（字段：`inputTokens / outputTokens / cacheReadTokens / cacheWriteTokens`）→
**请求的真实上下文长度 = `inputTokens + cacheReadTokens`**，按时间排列即得增长曲线。

## 5. 未验证项（明确标注，避免误导）

| 说法 | 状态 |
|---|---|
| "抓帧与播放抢资源导致卡顿" | **怀疑**：时间上有相关性（20 次播放 12 次卡顿，卡顿前常有截图），**没做对照实验** |
| "上下文占用 >50% 开始退化" | **未验证**：来自视频口播，无出处；我们只量到"占用多少"，量不到"变笨多少" |
| "把固定流程写成 skill 单次省 1 万 token" | **单样本**，不足以当普遍收益 |
| 压缩触发阈值 | **已核实（本机实现）**：`floor(min(W×0.8, W − O − 65536))`，即 1M 窗口下约 54%~80%，取决于输出预留 |

## 6. 怎么自己量（而不是相信这份文档）

```powershell
# 环境与账本
bili-learn doctor
bili-learn spend

# 抓帧覆盖与读图成本（挑帧输出里每张都带"在场"时长）
bili-learn frames --dir <目录> --pick --want 8

# 转写覆盖率（每个转写文件头都会写）
Get-Content data/out/transcripts/*.md -TotalCount 6
```

**建议**：换账号/换地区后**先跑一遍你自己的样本**（比如 30 条目标视频），
把可用率、字幕覆盖率、平均时长量出来，再决定选题策略和预算——本文件的数字只做参考基线。
