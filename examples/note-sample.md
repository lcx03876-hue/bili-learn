## 可复用要点
- 放大分母：优先选上下文窗口大的模型。查窗口两法——切模型时悬停看提示；没标注就跑一次任务，占用率提示里的分母就是窗口大小 [00:10:07]。但换大窗口只是换更大的氧气罐，治不了耗尽 [00:10:52]。 → 落点：无（仅存档）
- 压分子（主手段）：任务执行中持续盯占用率，越过临界值就新开窗口重开任务 [00:11:15]。 → 我用在：learn/CONTEXT-HYGIENE.md 的收手信号表
- 跨窗口交接用 progress.md：让 agent 把当前对话整理进去，含已完成事项、关键决策、未完成待办 [00:11:56]；新窗口先读 progress.md 再接新指令 [00:12:31]。本质是手动压缩，只提炼关键信息。 → 我用在：learn/CONTEXT-HYGIENE.md 交接模板
- 固定流程任务改成 skill：同一"5 份简历提 7 个字段"任务，无 skill 63.2K（≈6.3%）、有 skill 49.8K（≈5%），单次省约 1 万 token，10 个任务累计省近 10 万上下文 [00:13:16]。原因是不给 skill 时 agent 靠自己摸索、易走弯路 [00:14:03]。 → 我用在：learn/CONTEXT-HYGIENE.md 压分子第 3 条
- 日常习惯：在 Claude Code / Codex / Trae / WorkBuddy 这类产品里，任务跑完顺手看一眼占用率，把它当成和"花了多少钱"同级的指标 [00:14:25]。 → 我用在：cd bili-bot; node bili.mjs cost

## 术语与概念
- 上下文占用率：当前占用的上下文长度 ÷ 模型上下文窗口大小，Agent 的"油表"。
- 上下文五块：系统提示词、工具定义、固定记忆与 skill、对话历史、当前任务；前四项是固定开销。
- 自动压缩（auto-compact）：占用率到 80%~90%（Claude Code 口径）时框架自动把历史摘要化，会丢信息且触发太晚。
- lost in the middle：长上下文下模型对首尾敏感、对中段细节不敏感。
- progress.md：专门写给 AI 看的项目进展文档，用于跨窗口接续任务。
- skill：把固定流程写成 agent 可执行的说明书，靠减少试错来降低 token 消耗。

## 存疑 / 待验证
- ">50% 开始退化、80%~90% 严重退化"是经验口径，视频没给实测出处；临界值值得自己跑一次对照（本机 DSH 的占用率读数可直接验证）。
- ✅ **已核实（2026-10-01，读本机 DSH 实现）**：DSH 自动压缩 `thresholdRatio` 默认就是 **0.8**，方向与视频吻合；但真实阈值是 `floor(min(W × 0.8, W − O − 65536))`，还要扣掉本次请求的输出预留 `O` 和固定 65,536 token 余量。以本机 deepseek-flash（1M 窗口）算：`O=8K` → 阈值≈80%，`O=384K` → ≈55%。**输出预留越大，压缩触发越早**，所以"80% 才触发"只在输出预留很小时成立。压缩时最近 16%（`retainRatio: 0.16`）逐字保留，并会先修剪超大工具输出再决定是否摘要。来源：`@deepseek-ai/dsh-compaction-basic` 的 `README.zh.md`。
- 举例的模型名与 100 万窗口（"GPT5.5 / Gemini3.5 / 智谱5.2 / DeepSeek V4 Pro"）疑似口误或超前型号，窗口大小以工具里实际显示的为准。
- 所有占用率数字来自 WorkBuddy + 智谱（20 万窗口），换到 Codex / Claude Code 不能直接套用。
- "skill 省 1 万 token"是单任务单点样本，样本量太小，不足以当作普遍收益。
